## Sprint Goal

Implement the weekly meeting schedule feature so users can enter, save, and view their meeting times under their own accounts.

## Sprint Backlog

### Card 4.1 – Input and Save the Weekly Meeting Schedule (UR1)

**User Requirement:** UR1 — Users can enter and save their weekly meeting schedule.

**Tasks:**
- Define the Meeting model with a user foreign key, title, start time, end time, day, and recurrence information.
- Create and apply the database migration.
- Build a form and view for manually entering meetings.
- Save meetings under the logged-in user's account.
- Display saved meetings on the schedule page.
- Write tests to verify that meetings save and load correctly for each user.

## Week 1 Plan

The goal for Week 1 is to complete approximately half of the backlog item.

- Define the Meeting model and apply the migration.
- Build the meeting form and view.
- Implement the ability to save meetings.
- Begin displaying saved meetings on the schedule page.

**Expected outcome:** The basic meeting entry and saving functionality is implemented, with the schedule display working or being verified.

## Week 2 Plan

The remaining work will be completed in Week 2.

- Finish verifying the weekly schedule display.
- Write tests for saving and loading meetings.
- Verify that each user can access only their own meetings.
- Run the test suite and fix any failures.
- Confirm that the Definition of Done is met.

**Expected outcome:** The weekly meeting schedule feature is tested and ready for completion.

## Definition of Done

- Users can enter and save weekly meeting times under their own accounts.
- Saved meetings are displayed on the schedule page.
- Users cannot access other users' meetings.
- Relevant tests pass.
- The team's global Definition of Done is satisfied.

## Progress Tracking

The backlog item will remain **In Progress** during Week 1. It will be moved to **Done** only after the remaining work and required testing are completed in Week 2.
